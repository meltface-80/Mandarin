Install the server

Run the server on an always-on machine on the same network as your speakers: Docker on Linux, or a Mac without Docker.

Install with Docker

On an always-on Linux machine on the same network as your speakers — a NAS, a Raspberry Pi 4/5 on a 64-bit OS, a home server. Fill in your music folders and time zone and copy the command.

Music folders on this machine 

    


    

      --network host is required. Speakers are found by multicast, which does not cross Docker's default bridge
      network, and they fetch audio from this machine's own address. Docker Desktop for macOS and Windows has no real
      host networking, so this needs a Linux host. On a Mac, install it without Docker: see below.
    

    

      A USB DAC on this machine is played by Mandarin Bridge for Linux, installed on the
      machine beside the container (one line); the container opens no sound device of its own, so it needs no
      --device /dev/snd or --privileged for sound.
    

    

      Keep the musicd-server-data volume. It holds the library database, play history, playlists, settings and
      the artwork and conversion caches. The command above is a swap, not a fresh start — re-run it to update.
    

    

      More than one music folder? Add each one above. A single folder is mounted as /music; with
      several, each becomes its own folder inside it — /mnt/nas/Albums as
      /music/Albums, /mnt/usb/Vinyl as /music/Vinyl — and the scan reads
      them all as one library. All are mounted read-only. More folders can be added later in Settings → Music
      Folders, from any drive or share mounted into the container.
    

    

      The MusicBrainz pack on another drive? The pack (Settings → Library Scanner) is 2 GB, kept in
      the data volume unless you choose a folder. To keep it on another drive, give its host folder above: it is
      mounted as /packs, writable (no :ro), and you choose /packs under Folder in
      the app. Leave the line in every time you re-run the command.

Install on a Mac

  
No Docker needed: macOS 14 or newer, Apple silicon or Intel. The Mac stays on, on the same network as your
    speakers. It does everything Linux does: Sonos rooms, streamers, the Android app, a USB DAC plugged into the Mac,
    and away from home.

  

    
  1. Open Terminal: press Command-Space, type Terminal and press Return.

    
  1. Paste this line and press Return.

    

      

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin/main/tools/mac/install.sh)"

    

    
  1. Answer what it asks. Your Mac's password, if asked, for Homebrew
      (nothing shows as you type; that's normal). Your music folder: a Finder window opens; click the folder
      your music is in, on the Mac or an external drive, and click Choose. Where to keep the
      MusicBrainz pack if you download it later (optional, about 2 GB). Keep awake, so the music
      doesn't stop. And Allow if macOS asks to let mandarin-server find devices on your network or open
      your files.

    
  1. Done. Mandarin opens in your browser: create your account, or use it
      without one. It starts by itself whenever you log in. On a phone, open the address Terminal shows at the end.

    
On a Mac, as on Linux: updates come from the app (Settings → Updates). A USB DAC: switch it
      on in Settings → Audio Devices; Mandarin plays it through Core Audio at each track's own rate, holding it
      while it plays. Away from home: Settings → Away from home. Your data is kept in ~/Mandarin/data.

    
Shut down and start again: the power button at the top right of the side menu (☰)
      → Shut down stops Mandarin; double-click Mandarin on the desktop to start it again. It also starts
      when you log in. No albums? In System Settings → Privacy & Security → Full Disk Access,
      click +, press Command-Shift-G, paste ~/Mandarin/server/bin/mandarin-server and click Open.

  


  
Updating

  
In the app: Settings → Updates → Check for update beside the server → Update
     available. The server downloads the new release from GitHub, checks it against the release's sums, swaps it in
     and starts again in a few seconds; a browser's page reloads on its own. In the Android app the app has its own
     Check for update beside it, and each Mandarin Bridge has a row of its own. It also checks twice a day and
     shows a banner when a new version is out.

  
The new program is laid in beside the old before anything is swapped: if something fails after the swap, the old
     one is put back. If it can't start again in place, Docker's restart policy (--restart unless-stopped)
     starts the container again.

  
By hand — also the way to pick up changes to the image itself (ffmpeg, the audio engine):

  


docker pull ghcr.io/meltface-80/musicd-server:latest
docker stop musicd-server && docker rm musicd-server
# re-run the docker run command above — the data volume carries everything over



  
A docker-compose.yml is in the repository too: set your music path and run
     docker compose up -d.
