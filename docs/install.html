Install the server

Run the server on an always-on machine on the same network as your speakers: on Mandarin OS, the recommended way, or on Linux as the alternative.

  • Mandarin OS, recommended: a computer of its own for Mandarin, installed from a USB stick, with a web page of its own to watch over everything and nothing else to look after.
  • On Linux, the alternative: natively on a Debian, Ubuntu or Raspberry Pi OS machine you already run, beside what else it does, with one command.

Mandarin OS (recommended)

A lightweight operating system made only to run Mandarin Server, on a computer of its own (a mini PC such as a Dell OptiPlex Micro or an Intel NUC), with a web page of its own, the system page, to watch over and look after everything. Write its image to a USB stick, start the computer from it and answer a few questions; from then on it looks after itself, with a shared folder, smb://<box address>/data, for your music, and USB drives mounted as they are plugged in. From 0.1.4 it updates itself in place, and goes back by itself to the version that worked if a new one doesn't start (Updating Mandarin OS; 0.1.3 and earlier reinstall once to get it).

  1. Download the imagemandarin-os-0.1.6-x64.img.xz for balenaEtcher or a Linux terminal, mandarin-os-0.1.6-x64.img for an Android phone. Downloads
  2. Make the USB installerWith balenaEtcher, dd or EtchDroid, on a stick of 4 GB or more. How
  3. Install itSecure Boot off, start the PC from the stick (F12 on a Dell), and choose its disk, the shared folder's user and password, and the network. How
  4. Open Mandarinhttp://<box address>:3500, and the system page at http://<box address>/. Using Mandarin OS

Install on Linux (the alternative)

Mandarin installed natively, for a Linux machine you already run. On an always-on Debian, Ubuntu or Raspberry Pi OS machine (64-bit, x64 or arm64) on the same network as your speakers, one line as root:

curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin/main/tools/linux/install.sh | sudo bash -s -- --music /srv/music
It installs what Mandarin needs from apt, makes a user of its own (mandarin, in the audio group), runs Mandarin as a systemd service (mandarin.service) now and at every start, and keeps its data in /var/lib/mandarin. Without --music, it keeps the music folder it had (a first install takes /music); more can be added in Settings → Music Folders.
OptionWhat it does
--music DIRThe music folder (/srv/music above).
--port NThe port (3500).
--data DIRThe data folder (/var/lib/mandarin).
--uninstallThe service and /opt/mandarin removed; the data kept.
--purgeRemoved, its data too.

To update, use Settings → Updates (below), or run the line again with the same options: the library, the account and the settings are kept. Run it with another --music to change the music folder. To remove it:

curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin/main/tools/linux/install.sh | sudo bash -s -- --uninstall
A USB DAC on this machine is played by Mandarin Bridge for Linux, installed beside the server (one line).
  1. Open http://<server-ip>:3500 (on Mandarin OS too: its screen shows the address) on a device at home and create your account — one username and password, kept on the server — or choose Use without an account (a TV needs nothing typed). The first scan starts straight away; albums appear as it goes.
  2. Pick a room under Settings → Audio Devices, or from the speaker button on Now playing.
  3. Tap an album and Play Now.

Updating

In the app: Settings → Updates → Check for update beside the server → Update available. The server downloads the new release from GitHub, checks it against the release's sums, swaps it in and starts again in a few seconds; a browser's page reloads on its own. In the Android app the app has its own Check for update beside it, and each Mandarin Bridge has a row of its own. It also checks twice a day and shows a banner when a new version is out. On Mandarin OS, Mandarin updates the same way, and Mandarin OS itself from its system page (Updating Mandarin OS).

The new program is laid in beside the old before anything is swapped: if something fails after the swap, the old one is put back. If it can't start again in place, its systemd service starts it again.
