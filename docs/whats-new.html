What's new in v1.3.1

Mandarin v1.3.1, since v1.3.0, with Mandarin Bridge v0.3.10 and Mandarin OS 0.1.4. Mandarin OS arrives, the recommended way to run Mandarin, with Mandarin on Linux as the alternative; logs are always on and download as one file; and a handful of fixes.

Mandarin OS 0.1.4

A lightweight operating system made only to run Mandarin Server, on a PC of its own, with its own system page (http://mandarin/) to watch over and look after everything: a shared folder for your music, USB drives mounted as they are plugged in, and a weekly upkeep when nothing plays. Installed from a USB stick made with balenaEtcher, a Linux terminal or EtchDroid on an Android phone. It updates itself in place, and goes back by itself to the version that worked if a new one doesn't start. The recommended way to run Mandarin. Mandarin OS →

Mandarin on Linux, natively

The alternative, for a Debian, Ubuntu or Raspberry Pi OS machine you already run (x64 or arm64): one line as root installs what Mandarin needs and runs it as a systemd service, its data in /var/lib/mandarin. Run again, it updates; --uninstall removes it. Install on Linux →

Logs always on, as one file

The server, every Mandarin Bridge, the Android app and the page keep a log always, all of it on the server. Settings → Setup → Logs → Download all logs in a browser gives every log as one text file, in time order, each line saying where it came from; the app's Save log and Mandarin OS's system page do the same. Logs →

  • Fixed: a large library's backup restores, where it was refused as “too large”.
  • Fixed: while MusicBrainz is turning requests away, every lookup pauses (a minute, then longer, an hour at most), where it asked again every few seconds.
  • Fixed: a Mandarin Bridge switched on in Settings → Audio Devices stays on, even while Qobuz's library is updated; a change the server refuses is said.
  • Fixed: Mandarin Bridge 0.3.10 for Linux updates itself where systemd runs it, as on Mandarin OS.
  • Fixed: the Android app pauses between tries when the server can't be reached, where it asked again and again.
  • Changed: what Mandarin says to do (a forgotten password, an empty library, no rooms) fits how it is installed; on Mandarin OS, Shut down shuts the computer down too, and its power button starts it all again.
Updating: the server from Settings → Updates, the Android app beside it, each Mandarin Bridge from its own row. Mandarin OS updates itself from its system page; 0.1.3 and earlier reinstall 0.1.4 once (how). Every change is listed in the changelog.

Before: v1.3.0

Mandarin v1.3.0, since v1.2.5, with Mandarin Bridge v0.3.8. An update following a code review: several under-the-hood fixes and improvements.

Last.fm scrobbling

Everything played, in every room, on a Mandarin Bridge or the phone, is scrobbled to your Last.fm account. Save your Last.fm key's shared secret beside the key in Settings → Setup → API Keys, tap Connect to Last.fm and allow Mandarin on Last.fm's page. Features →

An artist's page in tabs

Overview, Discography and About, as an album's page has, with no links out to the web. Similar albums are your own library's alone, and genres are in English everywhere (Électronique is Electronic).

  • Removed: Playlists and Dynamic Playlists, with Qobuz's and Tidal's playlists and favourite tracks brought in as playlists (favourite albums still are).
  • Fixed: plays, scrobbles and covers kept right through skips, drives mounted late and a DAC unplugged; a USB DAC pulled out of the phone pauses it, as headphones do; Mandarin Bridge 0.3.8.
  • Improved: security, speed and reliability across the server, the page, the app and Mandarin Bridge. Releases are signed, and the server and Mandarin Bridge install only a signed update.
Updating to v1.3.0: the server from Settings → Updates, the Android app beside it, each Mandarin Bridge from its own row. Every change is listed in the changelog.

Before: v1.2.5

Mandarin v1.2.5, since v1.2.2, with Mandarin Bridge v0.3.4.

Versions of one album, one album

An original and its remaster are one tile, 2 versions under it. Versions are told by MusicBrainz's release group, else one act and one title with its version words off (2015 Remaster). The main is the highest resolution, or the one you choose with Make this the main version; the album's page lists every version with what tells it apart, a tap showing it in place. Features →

An album's page on a phone, redesigned

The cover on top, the date, rate and length under it, the title across the page; then Tracks, Credits, About and Versions as tabs, centred, held at the top as the page scrolls with the page cut off cleanly under them. Share card is in ⋯. In the browser and the Android app.

Clipping shown, and Headroom when upsampling

A track mastered to full scale clips between its samples when upsampled. Mandarin now counts every clipped sample and turns Now playing's line red; Headroom when upsampling (Auto) turns a track down by just what its true peak needs. Upsampling →

Keeping up, and a safety net

The signal path says how fast a track is being made (Keeping up at 4.2× real time). An Output the server can't make in time, or the device can't play, is put back to the last one that played well, the track carrying on. Signal path →

Changed

  • The music folders are followed as they change: an album shows as it is copied in, a deletion within seconds, and a network share's or a mergerfs folder's changes within half a minute, where they waited for the six-hourly scan.
  • Search's count (1 artist, 60+ albums) is under the search field, which keeps its width.
  • Extended ends an edition's title, as Deluxe and Remastered do: Radical Optimism (Extended) is a version of Radical Optimism.

Security

A security audit of this version found fourteen things to put right; every one is fixed.

  • Who sent a request is believed from forwarding headers only from the proxies named in TRUSTED_PROXIES and the built-in Tailscale. A reverse proxy on the same machine needs TRUSTED_PROXIES=127.0.0.1. Configuration →
  • Covers from elsewhere are never fetched from the server's own machine or your network (but the Sonos speakers and hosts named in ART_HOSTS).
  • Addresses handed to speakers and players expire after 30 days, and a speaker asking without one gets only what it was handed.
  • Mandarin Bridge's port takes changes only as JSON, never from another site, and never updates backwards. A page on another port of the server's machine can't use your browser's sign-in either.
  • Scripts run only from Mandarin's own pages (a Content-Security-Policy).
  • With the sign-in off, only your own Tailscale devices count as home, not all of Tailscale's address range.
  • Releases can be signed, and the server's and the Linux Bridge's updates checked against Mandarin's release key.
  • Away from home, use Tailscale, never a port forward: the log now says when plain http arrives from outside. The workflows' actions are pinned, and a build that can be published needs the real signing key. Away from home →

Fixed

  • An album that mixes sample rates played nothing with Albums as one stream on, when its Output made DSD or upsampled to the highest rate.
  • An album deleted from the music folders stayed on its artist's page, in the app and the browser.
  • The Android app's album tabs were squashed into a column of letters, and the headings under them said the tabs again.
  • Mandarin Bridge's update said only SecureConnectionError when GitHub's certificate was refused; it now says why (a wrong clock, missing certificates).
Updating to v1.2.5: the server from Settings → Updates; the Android app beside it; each Mandarin Bridge from its own row. A reverse proxy on the server's machine needs TRUSTED_PROXIES=127.0.0.1. Every change is listed in the changelog.
