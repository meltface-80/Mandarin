How it works

Mandarin is a server and an Android app. The server scans your library and plays it to Sonos rooms, UPnP/DLNA streamers, Mandarin Bridges and the Android app.

Tracks go into the speaker's own Sonos queue; a streamer is handed each next track ahead of time. Each device fetches the audio from the server: the file itself when it can play it, converted to what it takes when it can't.

  • Library. The music folders are walked and every audio file's tags are read into a database. Albums are decided a folder at a time, so CD1/CD2 folders become one album. Covers come from cover.jpg/folder.jpg or the first track's picture; an album with none gets one drawn. Rescans only re-read files whose size or date changed.
  • Album names. The identification scan looks each album up by what its files carry (a release id, barcode, catalogue number), then by name on MusicBrainz and iTunes, scoring each release against the tracks and their lengths. Names are laid over the album, never written to your files.
  • Credits and artists. In the background, who played, sang, wrote and made each album, and who each act is, from MusicBrainz and Wikidata, with a picture from FanArt.tv, Wikidata or Deezer.
  • Streamers. Found on the network, each one's description read for what it can play, and played through its own transport, the next track handed over ahead of time (gapless where it supports it).
  • Sonos. One speaker is found and the whole household is read from it; tracks go into the coordinator's own Sonos queue, so the speaker moves between tracks by itself.
  • The interface. Mandarin's own page, served by the server, in the browser and the iPhone home-screen app; the Android app draws the same screens natively.
  • The server. One program in C#, built to a single file: nothing else needed to run it.

For how your music is found and named, in plain words, there is a guide on Downloads.
