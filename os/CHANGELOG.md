# Mandarin OS changelog

## v0.1.1

- Fixed - a stick written from a phone (EtchDroid, Etcher on Android) didn't start the computer: those apps write the file as it is, and the image was published only compressed (.img.xz), so the stick held compressed bytes. The image is published as it is as well (.img, about 1.6 GB), for apps that don't decompress, beside the .img.xz for those that do (balenaEtcher, Raspberry Pi Imager, xz | dd); each with its checksum and signature. The test-os pre-release holds only the newest version's files
- New - Shut down in Mandarin shuts the computer down: Mandarin writes "poweroff" in /run/mandarin-os/power/request (a folder only Mandarin's group can write), and mandarin-os-power.path acts on it as root, on that word alone, removing the request either way
- New - the system page, http://mandarin/ (or the box's address), as ROCK's: Overview (Mandarin answering, its version and library, and each of its services running or not), Storage (the data partition's space; each USB drive, read-only and why, and Eject; internal storage, a second internal disk formatted for it, typed "erase" first, and never the system's disk or a USB drive), Network & Access (the address now, DHCP or a static address checked before it's taken and put back by itself after two minutes unless kept from the new address, a connection test layer by layer, the share and its user), Settings (Mandarin Bridge installed or removed, the weekly upkeep's last run) and Support (Mandarin's, the system's and this start's logs read and filtered, all of them as one zip; Reinstall Mandarin; Reset Mandarin, its data set aside in its backups). The power menu restarts Mandarin, restarts the computer or shuts it down. Read without a password; every change asks for the share's, checked as Samba keeps it, and five wrong in five minutes stop it trying for five minutes. It answers only under the box's own names and addresses, and a change only from its own page
- Fixed - Sonos speakers were never found: the firewall let in a speaker's answer to Mandarin's search only from port 1900, and Sonos answers from a port of its own. UDP from the home network is let in (nothing else on the box listens), and the router's multicast queries (IGMP), so speakers' announcements keep reaching it. os/test/firewall-test.sh proves it between two network namespaces, the old rules dropping the answer
- Changed - a test image (test-os) carries Mandarin as dev is now, built from the same commit with its audio engine (os/mandarin-from-source.sh): dev's built-in Tailscale, always-on logs and words; a numbered Mandarin OS release carries Mandarin's latest release
- New - passwordreset at the box's screen: Mandarin's account removed and every device signed out, for a password forgotten (there is no shell to run reset-password in); the login page says so on Mandarin OS. Mandarin knows it runs on Mandarin OS (MANDARIN_OS)
- Fixed - the USB stick started with a screen of "Timed out waiting" and "Dependency failed", taken for an error, and only then the installer, about half a minute later: it waited for a data partition and internal storage only an installed system has, and tried to mount its own partitions as music drives. Those mounts are written into the installed system by the installer now; on the stick nothing waits for them and nothing that needs them starts. The installer comes as soon as the stick has started, without waiting for the network, and the screen shows the installer or where to find Mandarin and nothing else (systemd's start-up lines go to the serial port). The system's own disk and Mandarin OS's own partitions are never mounted as USB drives. And an installed system no longer waits about two minutes at every start for systemd-networkd, which ran beside NetworkManager, managed nothing, and failed after its wait; NetworkManager alone runs the network

## v0.1.0

- New - Mandarin OS: Debian 13 with Mandarin installed natively, installed from a USB stick onto a computer's own disk; the share smb://mandarin/data for the user chosen at install, laid out as ROCK's Data share (Storage to copy music into, the logs read-only); USB drives mounted as they are plugged in, checked first; found as mandarin.local and by Windows; no login and no SSH, everything else closed by a firewall; a weekly upkeep, when nothing plays, of security updates and clean-up, restarting only when an update needs it and repairing whatever doesn't work after; networkreset at the screen for a static address that lost it
